Les deux sources de données

Source principale
DVF — Demandes de Valeurs Foncières
Base de toutes les transactions immobilières en France depuis 2014. Publiée par la DGFiP, elle contient l'adresse, le prix, la surface, le nombre de pièces, le type de bien et les coordonnées GPS de chaque transaction.
files.data.gouv.fr/geo-dvf/latest/csv/
Source croisement
BODACC — Bulletin Officiel des Annonces Civiles
Registre officiel des annonces légales : ventes et cessions de fonds de commerce, procédures collectives, radiations. Utilisé ici comme proxy de signaux d'activité économique pouvant accompagner un changement de situation.
bodacc-datadila.opendatasoft.com
Note importante : Le BODACC ne contient pas les successions de particuliers — celles-ci ne font pas l'objet d'une publication légale accessible. Le signal "succession" dans ce pipeline est un proxy basé sur des patterns de vente, pas une donnée directe.
02 — Signaux détectés

Les 5 signaux d'événements de vie

Chaque signal correspond à une logique de détection différente. Ils sont combinés pour produire un score de propension à vendre.

Signal 1 — Divorce
Revente rapide
Un bien T3 ou T4 revendu moins de 3 ans après son acquisition. Proxy fort d'une séparation ou d'un divorce nécessitant la liquidation du bien commun.
Score : 60 (délai 1-3 ans) / 80 (délai <12 mois)
Signal 2 — Naissance
Upgrade famille
Propriétaires de T1/T2 achetés il y a 2 à 4 ans. Profil typique des jeunes couples qui ont besoin d'espace après l'arrivée d'un enfant.
Score : 55 (base) — enrichi selon ancienneté
Signal 3 — Retraite
Downsizing
Grands biens (T5+) vendus avec une décote de plus de 10% par rapport à la médiane de la commune. Signal d'urgence de vente ou de libération de capital.
Score : 65 (décote 10-20%) / 80 (décote >20%)
Signal 4 — Primo
Primo-acheteur
Petits biens acquis sous 70% de la médiane du code postal. Ces acquéreurs seront des acheteurs de seconde main dans 5 à 7 ans, à cibler dès maintenant pour entretien de la relation.
Score : 50 (base)
Signal 5 — Succession
Héritage (proxy)
Croisement entre annonces BODACC dans un département et les ventes DVF dans les 18 mois qui suivent. Proxy imparfait — le BODACC ne publie pas les successions de particuliers.
Score : 50 (base) + délai + adjudication

Calcul du score de propension

Chaque prospect reçoit un score entre 0 et 100 basé sur plusieurs critères cumulatifs :

# Exemple — signal divorce/revente
score_base = 50

# Critère 1 : rapidité de revente
if delai_jours < 365:
    score += 30   # revente < 1 an
elif delai_jours < 730:
    score += 20   # revente 1-2 ans
else:
    score += 10   # revente 2-3 ans

# Critère 2 : adjudication (vente forcée)
if nature_mutation == "Adjudication":
    score += 20

# Critère 3 : décote prix marché
if decote_pct > 20:
    score += 15

score = clip(score, 0, 100)
03 — Configuration

Paramètres du pipeline

Tous les paramètres sont définis en tête de fichier et passables en ligne de commande.

ParamètreDéfautOptionsDescription
DEPT "75" 01 → 976 Code département INSEE. Fonctionne pour tous les départements métropolitains et DOM-TOM.
ANNEE 2024 2014 → 2024 Année des transactions DVF. Le DVF est disponible depuis 2014.
MOIS_LOOKBACK 24 6 → 60 Fenêtre de recherche en mois pour le croisement BODACC. Plus large = plus de matches, mais moins précis.
DATA_DIR ./data Tout chemin Répertoire de cache des fichiers téléchargés. Les fichiers sont mis en cache pour éviter les re-téléchargements.

Lancer le pipeline

# Installation des dépendances
pip install pandas numpy requests

# Lancer sur Paris, année 2024 (défaut)
python dvf_bodacc_croisement.py

# Lancer sur Lyon (69)
python dvf_bodacc_croisement.py --dept 69 --annee 2024

# Lancer sur Marseille, données 2023
python dvf_bodacc_croisement.py --dept 13 --annee 2023

# Résultat → data/prospects_69_20241201.csv

04 — Limites & biais

Ce que le pipeline ne fait pas

Comprendre les limites est essentiel pour ne pas sur-interpréter les résultats.

⚠ Limites importantes
  • Pas de noms ni contacts — le DVF ne contient pas l'identité des vendeurs. Le pipeline identifie des adresses et des patterns, pas des personnes.
  • Succession = proxy indirect — le BODACC ne publie pas les successions de particuliers. Le signal "héritage" est une corrélation temporelle, pas une cause avérée.
  • Données passées ≠ intentions futures — une transaction enregistrée en 2024 est déjà réalisée. Le signal indique un quartier/profil actif, pas un bien à vendre aujourd'hui.
  • Faux positifs sur upgrade — un T2 acheté il y a 3 ans peut avoir été vendu sans lien avec une naissance.
  • BODACC = commerce, pas particuliers — les annonces BODACC concernent principalement des fonds de commerce et des entreprises.
  • Pas de données en temps réel — le DVF est mis à jour trimestriellement avec un décalage de 3–6 mois.
✓ Ce que le pipeline fait bien
  • Segmentation géographique précise — identification des zones à forte propension par code postal ou arrondissement.
  • Scoring relatif fiable — les scores permettent de prioriser des zones et des types de biens, même s'ils ne sont pas absolus.
  • Volume exploitable — des milliers de signaux par département pour alimenter des campagnes publicitaires ciblées.
  • Reproductible et automatisable — peut tourner mensuellement pour suivre l'évolution du marché.
  • 100% données publiques — aucun risque légal lié à l'acquisition des données sources.
  • Enrichissable — base idéale pour croiser avec d'autres sources (INSEE, notaires, CRM).
Usage recommandé : utiliser le CSV comme base de segmentation pour des audiences publicitaires (Meta, Google) par zone géographique, et non comme liste de prospection directe nominative. Pour la prospection directe, un enrichissement via un prestataire habilité (RGPD) est nécessaire.
05 — Conformité RGPD

Cadre légal et bonnes pratiques

Le traitement de données à des fins commerciales est encadré par le RGPD et la loi Informatique et Libertés. Voici ce qui est autorisé, en zone grise, ou interdit.

✓ Autorisé
Ciblage géographique

Utiliser les codes postaux et communes pour cibler des campagnes Meta/Google sur des zones à forte propension.

✓ Autorisé
Segments publicitaires agrégés

Créer des audiences similaires (Lookalike) à partir de visiteurs de votre site sans traitement nominal.

✓ Autorisé
Analyse statistique interne

Utiliser les données agrégées pour comprendre le marché et adapter une stratégie commerciale.

⚠ Zone grise
Prospection postale

Envoyer un courrier à une adresse identifiée sans consentement préalable. Possible sous conditions avec base légale "intérêt légitime" documentée et droit d'opposition.

⚠ Zone grise
Enrichissement d'adresses

Croiser les adresses DVF avec un annuaire pour retrouver des noms. Possible uniquement via un prestataire habilité avec consentement géré.

✗ Interdit
Fichier nominatif direct

Constituer une base Nom + Adresse + Événement de vie sans base légale explicite (consentement ou contrat). Sanction CNIL possible.

Recommandation : La voie la plus sûre est d'utiliser les insights géographiques du pipeline pour créer des landing pages SEO thématiques ("Vendre suite à une succession", "Vous vous séparez ?") et des campagnes Meta/Google ciblées géographiquement. Le prospect vient à vous avec son consentement implicite — conformité RGPD garantie.
06 — Guide d'utilisation

Prise en main pas à pas

1
Installer les dépendances Ouvrir un terminal dans le dossier du projet et lancer pip install pandas numpy requests. Python 3.8+ requis.
2
Configurer le département cible Modifier la constante DEPT en tête de fichier (ex : "69" pour Lyon) ou passer --dept 69 en argument.
3
Lancer le pipeline python dvf_bodacc_croisement.py --dept 69 --annee 2024. Le script télécharge automatiquement le DVF (~50–200 MB selon le département) et les données BODACC.
4
Analyser le CSV de sortie Le fichier data/prospects_69_YYYYMMDD.csv contient tous les prospects triés par score décroissant. Ouvrir dans Excel ou importer dans un CRM.
5
Segmenter et activer Filtrer par signal et score_signal ≥ 70 pour extraire les prospects chauds. Utiliser les codes postaux pour créer des audiences publicitaires géolocalisées.
6
Automatiser Planifier une exécution mensuelle via cron ou Windows Task Scheduler pour maintenir la base à jour. Le cache évite les re-téléchargements inutiles.

Intégration CRM recommandée

# Exemple : import dans HubSpot via API
import pandas as pd
import requests

df = pd.read_csv('data/prospects_75_20241201.csv')

# Garder uniquement les prospects chauds
hot = df[df['score_signal'] >= 70].copy()

# Ajouter une colonne tag CRM
hot['hubspot_tag'] = hot['signal'].map({
    'divorce_ou_separation': 'PROSPECT_DIVORCE',
    'retraite_downsizing':   'PROSPECT_RETRAITE',
    'succession_bodacc':     'PROSPECT_HERITAGE',
})

# Export pour import manuel HubSpot
hot.to_csv('hubspot_import.csv', index=False)

Évolutions possibles

  • Connexion directe à l'API HubSpot ou Brevo pour injection automatique dans le CRM
  • Enrichissement des adresses via Nominatim (OpenStreetMap) pour obtenir des quartiers précis
  • Croisement avec les données INSEE (population, revenus par commune) pour pondérer le score
  • Alerte temps réel sur les nouvelles transactions DVF d'un secteur cible
  • Interface web pour non-développeurs (dashboard de suivi des prospects)
  • Export cartographique automatique (Folium/Leaflet) par département
